# 구글 간편 로그인

작성일: 2026-10-21

## 1. 적용 내용

로그인·회원가입 화면에 **Google 계정으로 로그인/가입** 버튼을 추가했다. 웹(`frontend`)과 모바일(`frontend-mobile`)에 같은 방식으로 적용했다.

- 처음 누르면 구글 계정의 이메일과 이름으로 가입하고 바로 로그인한다. 이름은 닉네임(20자까지)이 되며, 마이페이지에서 바꿀 수 있다.
- 다음부터는 같은 버튼으로 바로 로그인한다.
- 구글이 확인된 이메일을 주지 않으면 이메일 입력 화면을 띄운다. 입력한 이메일로 가입을 마친다. 이 단계는 카카오 로그인에서도 재사용할 예정이다.
- 구글로 가입한 계정은 비밀번호가 없다. 마이페이지에는 비밀번호 변경 대신 로그인 방법 안내가 보인다.
- 기존 이메일·비밀번호 로그인과 JWT 방식은 그대로다.

## 2. 동작 방식

```text
React (Google 버튼, 팝업)
→ 구글이 ID 토큰(credential)을 브라우저에 전달
→ POST /api/auth/social/google { credential }
→ 서버가 구글 공개키로 ID 토큰 서명·발급자·대상(클라이언트 ID)·만료 검증
→ social_accounts에서 (GOOGLE, 구글 사용자 ID)로 회원 조회
   ├ 있으면: 기존 JWT 발급
   ├ 없고 확인된 이메일이 있으면: 비밀번호 없는 USER 생성 + 연결 저장 + JWT 발급
   └ 없고 이메일이 없으면: EMAIL_REQUIRED (아무것도 저장하지 않음)
      → 화면에서 이메일 입력 → 같은 credential + email로 다시 요청
→ 이후는 이메일 로그인과 같다 (sessionStorage, Authorization: Bearer)
```

- 구글 ID 토큰은 서버에 한 번 보내 검증할 뿐 브라우저나 DB에 저장하지 않는다. 이메일 입력을 기다리는 동안에만 화면 메모리에 남는다(구글 토큰 유효시간 약 1시간).
- 서버 세션·쿠키를 만들지 않으므로 기존 Stateless 구조와 CSRF 설정을 바꾸지 않았다.
- 클라이언트 보안 비밀(client secret)은 필요 없다. 서버는 구글의 서명된 ID 토큰을 검증하는 방식이다.

## 3. 보안상 결정

| 상황 | 처리 | 이유 |
| --- | --- | --- |
| 구글 이메일이 이미 이메일 회원으로 가입됨 | `409 EMAIL_ALREADY_EXISTS`, 자동 연결하지 않음 | 이메일 인증이 없어서 다른 사람이 먼저 그 이메일로 가입했을 수 있다. 자동으로 합치면 그 사람이 비밀번호로 구글 사용자의 계정에 들어갈 수 있다. |
| 구글 계정의 이메일이 바뀜 | 기존 계정으로 로그인, 저장된 이메일은 유지 | 회원은 이메일이 아니라 구글 사용자 ID(`sub`)로 찾는다. |
| 구글 계정으로 비밀번호 로그인 시도 | `401 INVALID_CREDENTIALS` | 비밀번호가 없는 계정은 존재하지 않는 이메일과 같은 응답을 준다. |
| 구글 계정의 비밀번호 변경 | `400` (`currentPassword`) | 변경할 비밀번호가 없다. |
| 위조·만료·다른 앱용 토큰 | `401 INVALID_SOCIAL_TOKEN` | |
| 서버에 클라이언트 ID 없음, 구글 공개키 조회 실패 | `503 SOCIAL_LOGIN_UNAVAILABLE` | |

이메일 입력 단계에서 받은 이메일은 일반 회원가입과 같은 형식 규칙을 적용한다. 일반 회원가입처럼 실제 메일함 확인은 하지 않는다.

## 4. 설정 방법

### 4-1. Google Cloud Console

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들거나 선택한다.
2. **Google 인증 플랫폼(Google Auth Platform)** 에서 앱 이름·지원 이메일을 입력하고, 대상은 **외부**로 정한다.
3. 앱이 **테스트** 상태이면 등록한 테스트 사용자만 로그인할 수 있다. 팀원·시연 계정을 **테스트 사용자**로 추가한다.
4. **클라이언트 → 클라이언트 만들기**에서 유형을 **웹 애플리케이션**으로 고르고 **승인된 JavaScript 원본**을 추가한다.

   ```text
   http://localhost
   http://localhost:5173
   http://localhost:5174
   https://lost-quest-seho-8e2c.yseho.chatgpt.site
   https://lost-quest-mobile-seho.yseho.chatgpt.site
   ```

   팝업 방식이라 **승인된 리디렉션 URI**는 필요 없다.
5. 만들어진 **클라이언트 ID**(`….apps.googleusercontent.com`)를 복사한다. 공개 값이며 보안 비밀은 사용하지 않는다.

콘솔 메뉴 이름은 바뀔 수 있다. 최신 안내는 [Google 로그인 설정 문서](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)를 확인한다.

### 4-2. 백엔드

`backend/application-local.yml`에 추가한다(또는 환경변수 `GOOGLE_CLIENT_ID`).

```yaml
app:
  social-login:
    google:
      client-id: 복사한_클라이언트_ID.apps.googleusercontent.com
```

비워 두면 구글 로그인만 꺼지고 나머지 기능은 그대로다. 서버는 처음 구글 로그인 요청 때 `https://www.googleapis.com/oauth2/v3/certs`에서 구글 공개키를 받아 캐시하므로, 백엔드 PC가 인터넷에 연결되어 있어야 한다.

### 4-3. 프론트엔드

`frontend/.env.local`과 `frontend-mobile/.env.local`에 같은 클라이언트 ID를 넣고 Vite를 다시 시작한다.

```text
VITE_GOOGLE_CLIENT_ID=복사한_클라이언트_ID.apps.googleusercontent.com
```

값이 없으면 구글 버튼은 보이지 않는다.

- 로컬에서는 브라우저 주소를 `http://localhost:5173`(모바일은 `http://localhost:5174`)으로 연다. `127.0.0.1`이나 `192.168.x.x` 주소는 구글에 등록할 수 없거나 등록하지 않은 원본이라 버튼이 동작하지 않는다.
- 모바일 개발 서버는 `.env.local`의 `VITE_API_BASE_URL`도 `http://localhost:5174`로 맞추면 같은 주소에서 API를 호출한다.
- 휴대폰에서 같은 Wi-Fi의 PC 주소로는 구글 로그인을 시험할 수 없다. 배포된 Sites 주소를 사용한다.

### 4-4. Sites 배포

배포용 체크아웃의 `.env.production`에 `VITE_GOOGLE_CLIENT_ID`를 추가하고 다시 빌드·배포한다. Vite 값은 빌드할 때 들어가므로 파일만 고쳐서는 배포된 사이트에 반영되지 않는다. Sites 주소는 4-1의 승인된 JavaScript 원본에 있어야 한다. 이번 작업에서는 배포하지 않았다.

## 5. DB 변경

[SQL/08_구글_간편_로그인.sql](SQL/08_구글_간편_로그인.sql)을 새 서버를 실행하기 전에 적용한다.

- `users.password`를 NULL 허용으로 바꾼다. 구글로 가입한 회원은 비밀번호가 NULL이다.
- `social_accounts` 테이블을 만든다. `(provider, provider_user_id)`와 `(user_id, provider)`가 유일하다.

개발 프로필의 `ddl-auto=update`는 새 테이블은 만들지만 **기존 `password` 열의 NOT NULL은 바꾸지 않는다.** `ALTER TABLE`을 실행하지 않으면 구글로 처음 가입할 때 `409 DATA_CONFLICT`가 난다. 기존 회원·물품 기록은 바뀌지 않는다.

```sql
SELECT u.id, u.email, u.nickname, u.password IS NULL AS google_only, s.provider, s.created_at
FROM users u LEFT JOIN social_accounts s ON s.user_id = u.id;
```

## 6. 검증 결과 (2026-10-21)

- 백엔드: 구글 토큰 검증 단위 테스트 10개(임시 RSA 키로 서명한 토큰으로 정상·다른 앱용·다른 발급자·만료·다른 키·형식 오류·미설정·공개키 조회 실패 확인), 구글 로그인 API 테스트 13개(첫 가입, 재로그인, 이메일 회원과 충돌, 이메일 요청과 재요청, 이메일 형식, 닉네임 자르기, 비밀번호 로그인·변경 차단) 통과.
- 백엔드 전체 428개 중 425개 통과. 실패한 3개(경찰청 API 연결 시간 초과, 미래 날짜 검증, 커뮤니티 글 작성 제한)는 이번 변경 전 코드에서도 같은 개발 환경에서 똑같이 실패했다.
- 프론트엔드: 웹 626개, 모바일 640개 테스트와 두 빌드 통과. 구글 버튼 표시·숨김, 스크립트 로드 실패 안내, 이메일 요청 화면, 토큰 거절 시 처음 화면 복귀, 마이페이지 비밀번호 영역 확인.
- 브라우저: 구글 스크립트와 API를 가짜로 대신해 로그인 화면 버튼 배치, 이메일 입력 화면, 가입 후 이동을 데스크톱·휴대폰 폭에서 확인했다.
- 실제 구글 계정과 MySQL로 하는 확인은 클라이언트 ID 발급 후 따로 해야 한다.
