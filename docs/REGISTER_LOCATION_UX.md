# 등록 페이지 위치 입력 개선 및 향후 지도 선택 설계

## 이번 변경

- PC·모바일 등록 페이지의 `location` 초기값을 빈 문자열로 변경했다. 예시는 값이 아닌 `예: 성남시 단대오거리역 2번 출구 앞` placeholder다.
- 기존 HTML `required` 및 다음 단계의 `trim()` 필수 검사, 길이 제한 100자, API의 `region`·`location` 문자열 형식과 기존 공백 정리를 유지한다.
- 별도 등록 전용 CSS로 안내 간격·줄바꿈·대비를 지정한다. 경고는 `role="status"`로 알리고 두 필드의 `aria-describedby`와 연결한다. 오류로 처리하거나 진행을 차단하지 않는다.
- 판정은 입력한 장소의 **첫 공백 구분 단어**가 명확한 시·도 명칭일 때만 한다. 기존 17개 지역과 정식 명칭·일반 시도 약칭을 대응한다. `강원도/강원특별자치도`, `전라북도/전북특별자치도`도 같은 지역이다.
- 역·건물명, 시·군·구에서 상위 지역을 추정하지 않는다. `서울숲역`, `단대오거리역`, `성남시`, `광주시`에는 경고하지 않는다. `광주` 단독 표현은 경기도 광주시와 구분되지 않아 제외하고, `광주광역시`만 명확하게 인식한다.
- 여러 시·도 명칭이 등장하거나 첫 단어가 지역명이 아니면 보수적으로 경고하지 않는다. 주소 자동 완성·정규화·지오코딩이 아니므로 오탈자, 붙여 쓴 주소, 모든 불일치를 감지하지는 않는다.
- 실제 등록은 모의 API로만 검증한다. 새 지도 라이브러리 설치, 지도 API 호출, 좌표 저장, 실제 DB 쓰기 및 Sites 배포는 이번 범위에 없다.

## 향후 지도 선택 기능 (구현 전 설계)

1. **저장 계약부터 합의**: 별도 작업에서 분실물·습득물 각각에 선택적인 WGS84 `latitude`·`longitude`를 함께 추가한다. 둘 다 없거나 둘 다 있어야 하며 위도 -90~90, 경도 -180~180 및 유한 숫자를 서버에서 검증한다. 기존 클라이언트가 좌표를 보내지 않는 요청도 계속 허용한다. 현재 변경에는 API·스키마 수정이 없다.
2. **등록 UI**: 지역·필수 장소 텍스트를 유지하고, 실제 동작을 연결할 준비가 되었을 때 장소 검색과 핀 선택을 추가한다. 검색 결과나 지도 탭으로 좌표를 미리 선택한 후 사용자가 확인한다. 지도 이동만으로 좌표를 확정하지 않는다. 결과의 시·도나 주소 제안은 보여 주되 기존 입력을 몰래 덮어쓰지 않는다.
3. **입력 불일치 방지**: 핀 확정 후 장소 텍스트를 바꾸면 좌표를 지우거나 다시 확인하도록 한다. 확정 좌표·주소·정확도/출처 정보의 상태와 취소 동작을 명확히 한다. 사용자가 선택을 취소하거나 지도 연결에 실패해도 기존 텍스트 등록을 계속 지원한다.
4. **검색 제공자·운영**: 제공자의 사용 조건·학교 시연 환경을 확인한 뒤 결정한다. 필요하면 서버 프록시에 키를 보관하고 검색 디바운스, 요청 취소, 캐시·호출 제한을 설계한다. 이 문서 작성 과정에서는 제공자 API를 호출하지 않았다.
5. **상세 지도 연계**: 다른 작업자가 담당하는 상세 페이지와 공통 좌표 계약을 먼저 합의한다. 저장된 확정 좌표가 있으면 그 위치를 사용하고, 없으면 기존 장소 텍스트 및 현재 상세 페이지의 대체 표시를 유지한다. 추정 좌표를 확정 위치처럼 표시하지 않는다.
6. **과거 게시물 호환**: 기존 행은 좌표를 비워 둔다. 일괄 지오코딩이나 과거 장소 데이터 덮어쓰기를 하지 않는다. 향후 작성자가 명시적으로 위치를 선택할 때만 좌표를 저장한다.
7. **추가 검증**: 좌표 범위·쌍 검증, 좌표 없는 기존 요청/게시물, 검색 실패/취소, 핀 재선택, 텍스트 수정 후 재확인, 상세 지도 일치, 키보드 조작·390px 화면 및 개인정보 노출 범위를 확인한 뒤 별도 배포한다.

## 적용·검증 주의

- 작업 브랜치: `codex/register-location-ux`. 공유 `main`에는 병합하지 않는다.
- `ItemDetailPage.tsx`, `LocationMap.tsx`, `placeCoordinates.ts`, 기존 지도 CSS·패키지 설정은 변경하지 않는다.
- 기존 날짜 테스트는 이제 기본 장소가 없으므로 테스트에서 명시적으로 장소를 입력한다. 날짜 검증을 제거하거나 완화하지 않는다.
- 이번 worktree 빌드는 검증용이다. 향후 반영 시 변경 파일만 검토해 통합하고, 최신 다른 작업과 함께 다시 검사한다. Sites 배포 빌드는 당시 유효한 API 주소·모델 로딩 환경을 확인한 뒤 별도로 만든다. 검증용 dist를 바로 업로드하지 않는다.

## 검증 결과 (2026-10-22)

| 검증 | PC | 모바일 |
| --- | --- | --- |
| 전체 Vitest | 650/650 통과 | 664/664 통과 |
| 새 테스트 (위 전체 개수에 포함) | 39/39 통과 | 39/39 통과 |
| 등록·지역·날짜 대상 테스트 (전체에 포함) | 44/44 통과 | 44/44 통과 |
| TypeScript `tsc -b` | 통과 | 통과 |
| Vite `vite build` | 통과 | 통과 |

빌드는 기존 `npm run build`의 두 명령(`tsc -b` 및 `vite build`)을 순서대로 실행했다. 기존 의존성을 재사용했고 패키지/잠금 파일은 변경하지 않았다. 테스트는 Vitest 캐시를 꺼서 실행했다.

Chrome에서 PC 1440px·390px, 모바일 390px·768px의 lost/found 등록 총 8개 경우를 검증했다. 초기 공백·placeholder·HTML 필수 검증/포커스·키보드 Tab·경고 갱신·경고 상태에서 다음 단계 진행·가로 넘침 없음·버튼/고정 하단 메뉴 겹침 없음을 확인했다. 모바일 390px에서 다음 단계 버튼과 하단 메뉴 사이 간격은 약 75px였다. 화면 캡처로 안내 대비·줄바꿈도 확인했다.

모든 브라우저 API 요청은 모의 응답이었고 외부 요청은 차단했다. 지도 API 요청·실제 DB 등록은 없었다. 실제 휴대폰 터치·가상 키보드는 추가 확인 대상이다. 전체 테스트의 기존 jsdom `scrollTo` 미구현 진단은 테스트 실패가 아니며, 실제 Chrome 스크롤 검증은 통과했다.

검증용 산출물은 worktree의 `.local/register-location-checks/`에 있다. JSON 결과·빌드/타입 검사 로그·모의 API 브라우저 검사 코드·화면 캡처를 포함한다. worktree의 `dist`는 로컬 5191/5192 모의 API 검증용이며 원래 작업 폴더의 배포 산출물은 변경하지 않았다.

## 최신 main 기준 통합 검증 (2026-10-22)

- `git fetch origin main` 후 로컬 main과 `origin/main`이 모두 `a74ec88ab36eee0a2d1e2ade8e53d876eac462de`임을 확인했다. 상세 지도 PR #37이 main에 반영되어 있다. 등록 UX 브랜치는 이 커밋을 기반으로 하므로 적용 충돌이 없다.
- 공유 작업 트리에는 회의록 등의 미커밋 작업이 있어, 기존 별도 worktree에서 검증했다. 공유 main과 이 파일들을 덮어쓰거나 병합하지 않았다.
- 변경 파일 13개를 검토했고, 지도 컴포넌트·승인 좌표 데이터·패키지 설정·백엔드·검색·AI 매칭 코드는 변경하지 않았다.
- 최신 통합 코드로 PC 650개·모바일 664개 전체 테스트를 다시 실행해 모두 통과했다. 그중 기존 `ItemLocationPanel.test.tsx` 지도/카카오맵/장애 대체 테스트는 양쪽 각각 8개다.
- 양쪽 TypeScript `tsc -b`와 프로덕션 Vite 빌드를 재실행해 통과했다. 실제 Leaflet JS·CSS 청크도 양쪽 빌드에 포함됐다.
- Chrome 등록 검증 8개와 상세 위치 검증 8개(PC 1440px·390px, 모바일 390px·768px)를 통과했다. 상세 정보 탭에서는 지도 타일을 요청하지 않고, 위치 정보 탭에서 실제 Leaflet 코드와 마커를 렌더링함을 확인했다. 타일은 모의 PNG로 응답했다.
- 승인된 위치가 없는 모의 게시물은 지도 없이 장소 텍스트와 올바르게 인코딩한 카카오맵 검색 링크(`target="_blank"`, `rel="noopener noreferrer"`)를 표시했다. 등록·상세 위치 화면에 가로 넘침이 없고 모바일 등록 버튼은 하단 메뉴와 겹치지 않았다.
- 브라우저 API와 타일 요청은 전부 모의 응답이며, 실제 서버·DB·OSM·카카오맵에는 요청하지 않았다. OSM 실제 타일 연결과 물리 휴대폰 터치/가상 키보드는 전시 전 별도 확인 대상이다.
- 이번 작업은 좌표 저장을 추가하지 않는다. 새로 등록한 게시물이 기존 수동 승인 좌표 목록에 없으면 상세 페이지에서 카카오맵 링크를 사용하는 현재 정책을 유지한다.
- 통합 검증 로그·JSON·화면 캡처·브라우저 검사 코드는 `.local/register-location-integration/`에 있다. 이 worktree의 최신 `dist` 역시 5195/5196 모의 API 검증용이므로 배포하지 않는다. 배포하려면 승인 후 실제 API·모델 환경으로 별도 빌드하고 `LeafletMap-` 청크를 포함한 폴더 전체를 사용해야 한다.
